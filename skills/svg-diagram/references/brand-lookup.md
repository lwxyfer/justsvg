# Resolve a named brand

1. **User reference.** Use the exact screenshot, URL, product or campaign the user names. If that surface differs from a bundled profile, use the requested surface and inspect it separately.
2. **Bundled brand.** Extract the brand or supported product name from the brief. From the skill folder, run `python3 scripts/find_brand.py 'FigJam'`. The command returns one profile with its surface, sources, transferable design rules, historical evidence and example ID. `--list` prints the supported names and aliases. If Python is unavailable, search [brand-catalog.json](brand-catalog.json) and read only the matching record. A broad brand request may use its bundled surface as the working assumption. State the selected surface in the prompt.
3. **Unlisted brand or different surface.** Find the official page closest to the requested visual intent, such as a product screen, design system, campaign or editorial page. Inspect the actual visuals and identify the specific surface and date. When several plausible surfaces differ substantially, choose the one the brief supports and state the choice, or ask a focused question if the choice changes the direction. If access fails, use other valid official evidence or a user-provided capture. With partial evidence, record what supports the adaptation. Request a usable capture when fidelity is essential and no suitable evidence is available.

Apply [visual calibration](style-calibration.md) after selecting the surface. Reopen the selected source when the user asks for its current look or precise fidelity. A bundled profile is a dated project study. Record it as historical when fresh evidence is unavailable. Challenge pages, partial text, and screenshots each support different levels of visual claims. For example, the Notion paper-and-ink study has a recorded gap, and the J.P. Morgan study used provisional references.

The lookup uses exact normalized names, including case, punctuation and width variants. Exit code 1 returns `unlisted` or `ambiguous` in JSON. Continue with official source discovery for an unlisted name. Disambiguate a genuine collision using the brief.

Preserve the requested diagram semantics first. Transfer the brand's hierarchy, materials, type, shapes, rhythm and visual focus into that structure. Keep message order, branch meaning, row/column membership or quantitative scale legible. The catalog's example IDs identify the original RAG studies for optional comparison in a JustSVG checkout. The JSON itself is portable. Its entries suggest directions to try on new diagram types. The [Linear release flow](../examples/linear-release-flow.checks.md) records one actual cross-type trial.

## Maintain the catalog

The initial 39 entries are a snapshot of JustSVG's `brand-manifest.json` and the brand entries from `inspired-manifest.json`. Keep the bundled copy in sync when adding a study or recalibrating an existing one. Use the specific visual source as the first reference, strip RAG content and coordinates from the design rule, and preserve known access and fidelity limits in `recordedEvidence`. Add an alias only when it identifies the same surface or brand. Product branches with different visual languages require their own evidence. Verify that the normalized name and aliases resolve to the intended record.
