# Visual evidence and calibration

## Pin the surface

Record one primary visual anchor and the reason it applies. A company's marketing site, app, brand film and blog cover can have different visual languages. Use the user's exact screenshot/link first. Record a capture or observation date; a live site's first article can change. A screenshot of a challenge, blank state or login page is not a visual sample of the intended page.

Use available browser tools or a supplied local image to inspect the anchor. Research official specifications only when necessary; distinguish documented rules from measured/estimated observations. If access fails, retain the supplied evidence, state its age and scope, and mark unsourced decisions as provisional. Do not invent official tokens or fonts from memory.

## Convert observations into choices

Use this compact table in the prompt or check record. Populate observations with visible details, not adjectives such as “premium.”

| Dimension   | Observe                                                         | Decide for this diagram                             |
| ----------- | --------------------------------------------------------------- | --------------------------------------------------- |
| Composition | Where is the focal object? Which direction does reading follow? | Zones, hierarchy, whitespace, route corridors       |
| Scale       | How unequal are the objects and headings?                       | Focal node versus supporting nodes                  |
| Typography  | Alignment, weight, width, case, line spacing                    | Local fallback stack, sizes and label limits        |
| Lines       | Precision, weight, ends, dashes, arrow language                 | Distinguish functional edges from decoration        |
| Shapes      | Silhouettes, corners, containers, boundaries                    | Meaningful node kinds; avoid uniformity by default  |
| Material    | Flat, paper, metal, translucency, spatial color                 | Native vector approximation and readability changes |
| Icons       | Literal objects, outline glyphs, abstract marks                 | Concept-specific original geometry                  |
| Rhythm      | Density, repeated spacing, pauses, captions                     | Content-fit spacing and annotation positions        |

For alternatives, preserve semantics and evaluate these dimensions. For a new diagram in the same style, preserve the rules while adapting composition to its relationships. Uniform cards can suit a source with uniform cards; heterogeneous nodes are not a universal brand requirement.

## JustSVG case study: dated OpenAI blog observation

The project used a valid local capture of [OpenAI Developers Blog](https://developers.openai.com/blog), specifically the cover of “Designing failover across OpenAI model providers,” observed on 2026-10-25. This is a source-specific illustration direction, not an official diagram standard or a claim about the current first post.

Observed: white editorial surround, restrained centered title/subtitle, an uneven coral/orange/pink field with local cream light, translucent technical planes, fine authored glyphs, opposing concentric arcs. The [cover source](https://developers.openai.com/images/blog/designing-failover-across-openai-model-providers/cover.webp) identifies the reference; the package does not redistribute it.

Adapted: native linear/radial gradients, fine `pattern` stipple and clipping approximate the raster atmosphere. Dark wine text and functional edges replace pale information lines for legibility. Local sans-serif fallbacks approximate type without distributing proprietary fonts. Technical content can be denser than a cover. New examples must disclose these changes.

The historical local capture/DOM observation is not packaged. In this repo it is under `.impeccable/references/brands/openai-devblog-*`; final native renders and the two-item correction review are under `.impeccable/review/devblog/`. These are local audit evidence, not portable runtime dependencies. For new branded work, inspect a fresh source or the user's supplied capture. Without it, label reuse as a historical adaptation with current fidelity unverified.

## What the project established—and did not

- Recoloring the same four-above/five-below RAG template was rejected. Independent layouts, scales and objects better expressed the selected sources; layout uniqueness alone still does not establish fidelity.
- Blue/cyan corporate-color posters, a giant-circle OpenAI composition and a simulated ChatGPT interface were rejected directions for this task. They are not precedents for the pinned blog-cover request.
- Notion's retained paper/ink version was still judged lacking by the user. Keep it as an unresolved study, not a validated standard.
- Internal “ship” verdicts closed specified review items. They did not certify a brand or establish user aesthetic approval.
- Ten brand studies share nine RAG nodes/eight relations for controlled comparison. Basic variants intentionally preserve geometry. Neither experiment fixes a general diagram's topic, dimensions or node count.
